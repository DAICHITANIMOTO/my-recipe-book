# 自動レシピ生成手順（夜間エージェント用）

毎晩1回、クラウドの定期エージェントがこの手順を実行する。
手動セッションで「未処理の写真をレシピにして」と言われたときも同じ手順を使う。

## 写真の入り口

**`recipes/inbox/`** に直接コミットされた画像ファイル（.jpg / .jpeg / .png / .heic / .webp）。
`README.md` は無視。同名の `.txt`（例: `2026-09-06_193000.txt`）があれば「ヒント」として使う:
```
料理名: ガスパチョ
店名: バルさくら
日付: 2026-09-06
```
どの行も欠けていてよい。

> 注: GitHub Issue の添付画像（`github.com/user-attachments/...`）は、このクラウド環境の
> egressプロキシがリポジトリ外のURLをブロックするため取得できない。Issueで写真を受け取る
> 運用はしない（写真は必ず `recipes/inbox/` にコミットされた形で届く）。

## 手順

### 0. ブランチを整える
クラウド環境は detached HEAD で始まり `origin/main` 参照が古いことがある。最初に必ず：
```
git fetch origin main && git checkout -B main origin/main
```
以後この `main` 上で作業し、最後に `git push origin main`。

### 1. 対象を確認
`recipes/inbox/` の画像を一覧する（`README.md` は数えない）。1枚も無ければ
**何もせず「未処理なし」とだけ出力して終了**（commitしない）。

### 2. 画像を1枚ずつ処理
各画像について:

a. `Read` で画像の内容を見る。

b. ヒント `.txt` があれば読む。無い項目は次で補完:
   - 料理名: 写真から推定（例: 「オムライス」「アヒージョ」）
   - 店名: 不明なら空欄
   - 日付: ①ヒントの日付 → ②写真のEXIF撮影日（`exiftool -DateTimeOriginal <file>` 等、
     無ければ `identify -verbose` / `strings` で `datetime=` を探す）→ ③今日（`date +%Y-%m-%d`）
     の優先順。外食した実際の日を使いたいのでEXIFがあれば必ず優先する。

c. ファイル名の土台 `<土台>` = `YYYY-MM-DD_料理名`
   - 料理名は日本語、スペースと `/` は使わない
   - 同名の `recipes/*.md` があれば末尾に `_2`,`_3`…

d. 画像を移動: `git mv recipes/inbox/<元ファイル> recipes/画像/<土台>.<元の拡張子>`
   ヒント `.txt` があれば `git rm`。

e. `recipes/<土台>.md` を `レシピ雛形.md` をベースに作成:
   - frontmatter: `title`=料理名 / `date`=日付 / `restaurant`=店名（不明なら空）/
     `category`=推定（前菜／タパス／メイン／魚／肉／パスタ／スープ／サラダ／デザート など）
   - 本文1行目に固定で:
     `> ※この材料・作り方は写真と料理名からの推定です。実際に作って調整してください。`
   - 画像リンク: `![料理名](画像/<土台>.<拡張子>)`
   - `## 説明`: 写真とヒントから2〜4文
   - `## 材料（2人分）`: 写真と料理名から**推定**して分量つき箇条書き
   - `## 作り方`: 写真と料理名から**推定**して番号付き手順
   - `## メモ・感想`: `（食べたときの感想をここに書く）` のまま
   - `## 調整メモ`: `（実際に作ってみて気づいたことをここに追記する）` のまま

### 3. サイト再生成＆push
1件以上処理したら:
```
python3 build/サイト生成.py
git add -A
git commit -m "レシピ追加（自動）: <作った料理名をカンマ区切り>"
git push origin main
```
`build/サイト生成.py` は標準ライブラリのみ。`docs/` が GitHub Pages の公開元なので毎回更新する。
サイト生成でエラーが出ても、レシピの commit/push 自体は行う。

### 4. 出力
処理した件数・作成ファイル名・スキップしたもの（判別不能な画像など）を一覧で出力する。

## エラー時
- 画像が壊れている / 判別不能 → その画像は `recipes/inbox/` に残したまま、他の処理を続ける。
  最後に「スキップした」と報告。
- `git push` 失敗 → エラー全文を出力して終了（次の晩に再試行される）。
