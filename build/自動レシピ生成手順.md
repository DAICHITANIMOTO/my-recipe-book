# 自動レシピ生成手順（夜間エージェント用）

毎晩1回、クラウドの定期エージェントがこの手順を実行する。
手動セッションで「未処理の写真をレシピにして」と言われたときも同じ手順を使う。

## 写真の入り口は2つ

- **Issue（メイン）**：ユーザーがGitHubアプリから「新しいIssue」に料理写真を添付する。
  リポジトリは公開なので、Issue添付画像URL（`user-attachments` / `user-images.githubusercontent.com`）は
  認証なしでダウンロードできる。
- **inbox（サブ）**：`recipes/inbox/` に直接アップされた画像ファイル（.jpg/.jpeg/.png/.heic/.webp）。
  `README.md` は無視。同名 `.txt` があればヒント（`料理名:` `店名:` `日付:` の行、欠けててよい）。

両方を毎回チェックする。どちらにも新しい写真が無ければ **何もせず終了**（commitしない）。

## 手順

### 0. ブランチを整える
クラウド環境は detached HEAD で始まり `origin/main` 参照が古いことがある（作業ツリーの中身は最新）。
最初に必ず：
```
git checkout -B main HEAD
```
以後この `main` 上で作業し、最後に `git push origin main`。

### 1. Issue から取り込む
未認証で取得できる：
```
curl -sL "https://api.github.com/repos/DAICHITANIMOTO/my-recipe-book/issues?state=open&per_page=50"
```
`build/処理済みIssue.txt`（1行1番号）に**載っていない**オープンIssueだけが対象。
各Issueについて：

- `body` から画像URLを全部拾う（`![...](URL)` の URL、および本文中の生の
  `https://github.com/user-attachments/assets/...` `https://user-images.githubusercontent.com/...`）。
  1つも無ければそのIssueはスキップ（番号だけ `処理済みIssue.txt` に追記）。
- 画像を `curl -sL -o <一時ファイル>` で保存し、`Read` で内容を見る。
- **料理名**：`title` が具体的（"無題" 等でない）ならそれ、無ければ写真から推定。
- **店名**：`body` に「店名 …」「@…で」等があれば拾う、無ければ空欄。
- **日付**：Issueの `created_at` の `YYYY-MM-DD`。
- 下の「### 3. レシピを作る」に従ってレシピ生成＋画像配置。
- そのIssue番号を `build/処理済みIssue.txt` に追記。
- 可能なら `gh issue close <番号> -c "レシピに追加しました"` を試す（`gh` が無ければ無視してよい。
  再処理は `処理済みIssue.txt` で防いでいる）。

### 2. inbox から取り込む
`recipes/inbox/` の画像を1枚ずつ。ヒント `.txt` があれば読む（無い項目は下記で補完）。
処理した画像は `git mv` で `recipes/画像/` へ、ヒント `.txt` は `git rm`。
下の「### 3.」に従う。

### 3. レシピを作る（Issue由来・inbox由来 共通）
`recipes/<土台>.md` を `レシピ雛形.md` をベースに作る。`<土台>` = `YYYY-MM-DD_料理名`
（料理名は日本語、スペースと `/` は使わない。同名の `recipes/*.md` があれば末尾に `_2`,`_3`…）。

- 画像を `recipes/画像/<土台>.<拡張子>` に置く（Issue由来はコピー、inbox由来は `git mv`）。
- frontmatter：`title`=料理名 / `date`=日付 / `restaurant`=店名（不明なら空）/
  `category`=推定（前菜／タパス／メイン／魚／肉／パスタ／スープ／サラダ／デザート など）
- 本文1行目に固定で：
  `> ※この材料・作り方は写真と料理名からの推定です。実際に作って調整してください。`
- 画像リンク：`![料理名](画像/<土台>.<拡張子>)`
- `## 説明`：写真とヒントから2〜4文
- `## 材料（2人分）`：写真と料理名から**推定**して分量つき箇条書き
- `## 作り方`：写真と料理名から**推定**して番号付き手順
- `## メモ・感想`：`（食べたときの感想をここに書く）` のまま
- `## 調整メモ`：`（実際に作ってみて気づいたことをここに追記する）` のまま

### 4. サイト再生成＆push
1件以上処理したら：
```
python3 build/サイト生成.py
git add -A
git commit -m "レシピ追加（自動）: <作った料理名をカンマ区切り>"
git push origin main
```
`build/サイト生成.py` は標準ライブラリのみ。`docs/` が GitHub Pages の公開元なので毎回更新する。
サイト生成でエラーが出ても、レシピの commit/push 自体は行う。

### 5. 出力
処理した件数・作成ファイル名・スキップしたもの（判別不能な画像など）を一覧で出力する。

## エラー時
- 画像が壊れている / 判別不能 → その画像はスキップ（Issueなら番号を `処理済みIssue.txt` に入れて
  再処理を防ぐ、inboxなら `recipes/inbox/` に残す）。他の処理は続ける。最後に「スキップした」と報告。
- `git push` 失敗 → エラー全文を出力して終了（次の晩に再試行される）。
